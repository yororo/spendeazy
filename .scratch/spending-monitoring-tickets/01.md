## What to build

Users see Personal consistently throughout the application and Statement Import, and can find Budgets while retaining the four mobile tabs.

Scope: parent User Stories 1–4; ID-1.

## Acceptance criteria

- [ ] Resolve labels from actual Space identity/kind: an explicit Personal Space ID never displays Shared; the shell and all import stages show the correct Space.
- [ ] Retain the import destination lock when a file is accepted; labels and later commit destination remain consistent.
- [ ] Keep Dashboard, Imports, Transactions, and Insights as the four mobile tabs; rename the Categories menu destination to Budgets and retain Category management and existing route compatibility.
- [ ] Provide Manage Budgets from Dashboard and Monthly Insights without changing the selected Space or Reporting Period.
- [ ] Verify explicit-ID Personal routes on phone and desktop, existing authorization/cache isolation, accessible navigation, and updated design-system guidance.

## Blocked by

None — can start immediately.

## Implementation and validation guardrails

Use existing feature/page/service and isolated browser → API → PostgreSQL test seams. Each slice owns its meaningful regression tests and runs required owning-project checks plus the repository-required isolated end-to-end suite before completion. Preserve accepted Rule-storage/reconciliation ADRs, frontend feature boundaries, existing authorization and atomic import behavior; validate both sides of any discovered API contract adjustment. No new test framework, Review editing, numerical forecasts, automatic Budget changes, or private financial fixtures.
