## What to build

Users understand Remember's future benefit, opt into a predictable Exact Rule, and recover from failure or conflict without losing their draft.

Scope: parent User Stories 17–25; ID-6.

## Acceptance criteria

- [ ] Remember remains unchecked but prominent wherever useful, explains future-import benefits, and suppresses redundant encouragement for an equivalent Rule.
- [ ] Default to Exact; offer Contains explicitly with substring semantics and current-statement match preview. Preserve Exact precedence, normalized matching, inactive-Category restrictions, and reviewed assignments.
- [ ] Apply & remember persists the Rule immediately before the local assignment and confirms Rule saved for future imports; it is separate from atomic import confirmation.
- [ ] Rule failure/conflict applies no local assignment and retains all editor inputs; offer Retry and Apply without remembering.
- [ ] A conflicting normalized pattern/match type names the existing Category and is never silently replaced. Equivalent same-Category Rules are reused without duplicates.
- [ ] Leaving/discarding explains that draft Transactions are discarded but saved Rules remain. Handle uncertain network completion honestly and retry through equivalent-Rule reuse.
- [ ] Verify failure/retry, conflict, equivalence, immediate persistence before confirmation, draft discard, current suggestions/bulk coexistence, and Space-scoped authorization. Do not introduce distributed transaction semantics.
