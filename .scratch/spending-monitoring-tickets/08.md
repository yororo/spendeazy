## What to build

Users inspect every parsed statement row with clear expense/exclusion language and return to Categorize for corrections without losing their place.

Scope: parent User Stories 27–31; ID-7.

## Acceptance criteria

- [ ] Review contains no editing controls; one Back to Categorize action restores the previous sort, filters, and position.
- [ ] Show included expenses first in the chosen order and an expandable excluded section with reasons. Previous Categorize filters never silently hide Review rows.
- [ ] Keep a sticky included expense count and total reachable without obscuring rows, confirmation, or mobile navigation.
- [ ] Present expenses with positive readable amounts rather than green Credit based on internal parser sign; identify payments and other credits accurately using provider-supported information.
- [ ] Keep expense-only persistence and existing eligibility: payments/other credits remain excluded; eligible expenses can be re-included in Categorize.
- [ ] Preserve reconciliation, duplicate warnings, explicit confirmation, and atomic commit. Test hidden-by-filter rows, ordering within groups, exclusion reasons, Back restoration, and no-edit behavior across mobile/desktop.
- [ ] Preserve newer categorization/Remember functionality as it lands; this ticket does not need to wait for bulk assignment or Remember redesign to deliver read-only Review.
