# Adopt the mobile Expense domain through a breaking development contract

Accepted target decision, 2026-10-24. The canonical Expense storage and explicit Space route foundation is implemented by ticket [#142](https://github.com/yororo/spendeazy/issues/142); the mobile adapter and broader target workflows remain pending. [Specify the target Expense domain and mobile API contract](https://github.com/yororo/spendeazy/issues/132) and its [contract specification](../specifications/mobile-expense-domain-api.md) define the cross-project boundary. The root glossary owns the single shared domain: Expense is saved positive spending with a Category; Transaction is parsed mixed statement activity. The mobile glossary is a pointer. Technical database transactions and historical evidence keep their names.

We choose a clean development contract over compatibility and data-preserving conversion because existing Users/data are disposable development fixtures and the replacement's behavior deliberately differs from the former browser app. Financial routes name the authorized Space; saved Transaction routes and Personal financial aliases are removed without a compatibility window. Ticket [#141](https://github.com/yororo/spendeazy/issues/141) retired the browser source and hosting; ticket #142 applies the Expense schema and route foundation. Historical migrations remain evidence. The new migration aborts if a saved legacy row lacks a Category rather than guessing a reclassification. Seed/recreation requires an explicitly named disposable local database. This decision authorizes no live reset or deletion.

The target preserves independent identities, Personal privacy, equal Shared editing, immutable actor references, retained Expense Activity and permanent read-only archives. It extends uniform imported Expense edit/delete to Personal Spaces, requires Category and Manila-valid dates, uses current Category/person display labels in history, and changes account deletion from local access removal to retryable Personal-data/provider-identity/session cleanup while retaining Deleted user attribution in Shared history. New sign-up cannot inherit old access by email. External identity deletion and database cleanup require durable progress/fencing rather than a fictitious cross-system database transaction.

Category details, optional current Budget and its Rules save as one atomic draft, including inactive settings. Current Budgets apply retrospectively, without Budget versions/effective dates. Rules still evaluate only on-device; Exact precedence and ambiguity remain. A conflicting remembered Rule prevents all confirmation writes rather than silently replacing another Category's Rule.

Committed import provenance remains immutable and separate from changing Expense values. File/fingerprint matches become overridable warnings; a file hash is no longer unique. One logical confirmation has a distinct idempotent operation and recoverable status. Expenses, original evidence, remembered Rules, Activity and the successful result commit together. The minimal device receipt supports restart status while signed in but is cleared at explicit sign-out; it never stores the review draft or replays work automatically.

## Supersession and implementation status

- [Personal and Shared Spaces](0002-personal-and-shared-spaces.md): supersede saved Transaction naming, optional Category, Personal imported-edit restrictions, Personal-alias compatibility lifecycle and development-data-preserving rollout for this replacement. Retain Space ownership, equal authority, permanent archives, actor attribution, conflict protection and Invite Code supersession. The target makes account-deletion cleanup explicit; it does not unilaterally delete the other member's Shared history.
- [API Category Rule storage and replacement](../../api/docs/adr/0003-category-rule-storage-and-replacement.md): retain Space scope, normalized uniqueness, locking, revision checks and stable retained Rule identity. Supersede separate editor saves, active-only whole-Category replacement and immediate import-time Rule persistence with the atomic configuration/confirmation boundaries. Full inactive configuration maintenance is permitted; matching still excludes inactive Categories.
- [API route compatibility guidance](../../api/docs/route-compatibility.md): its former Personal-alias and saved-Transaction inventory is superseded. Space financial routes are current; no caller migration window is required. User profile, Space catalog/lifecycle and Invite Code routes remain.
- [Adopt Expense and Statement Entry terminology across Spendeazy](https://github.com/yororo/spendeazy/issues/118): supersede Statement Entry, web edits, old-data preservation, retained Personal aliases and its preserve-all-existing-financial-behavior premise. Its body is historical, not an executable replacement plan.

The code-first OpenAPI and feature-owned persistence ADRs are retained. OpenAPI and current architecture/database guides now describe the Expense foundation. They must continue to identify broader target areas that have not shipped, including the mobile adapter, atomic full Category configuration, durable import-operation recovery, complete import snapshots, and account-deletion orchestration. Automated API doubles do not establish device-reachable backend or real sign-in acceptance.
