# IP-04 Task 01 handoff

- `session.imports` owns the in-memory store; `statementImportStore` in `session-runtime.ts` is the production singleton. Do not instantiate another store in a route/controller. There is no navigation or AppState teardown, so Back/backgrounding do not discard it.
- Task 02 controllers must generate unique operation IDs for every selection/retry and capture the current session generation plus fixed User/Space before calling `start`. Deliver picker/hash failures and worker readiness through `deliver`; readiness is accepted only after `prepared` has supplied file identity. Coordinate host readiness with file preparation before sending that event. Use operation-fenced `cancel` for async cancellation and `discard` only for explicit current-work discard.
- Register synchronous, non-throwing byte/password/reference release with `onInvalidate` for each accepted operation. Invalidation removes the operation before calling these hooks on terminal outcomes, expiry, archive, sign-out or discard. Hooks are not asynchronous filesystem cleanup: Task 02 still owns worker teardown, file deletion, cleanup-failure reporting and startup recovery. No secret clearing or owned-file cleanup has been demonstrated on a device by this task.
- Recovery restores completed structured evidence; interrupted operations remain suspended with `reselection-required`. Even a replacement auth session for the same User invalidates an active operation. Read-only/archived Spaces retain ready evidence but cannot start another operation.
- `changeSpace` now returns whether the switch was accepted; live import work blocks it. Space list refresh also applies write access. If the bound Space disappears from the accessible list, refresh retains the import destination and suspends work rather than silently selecting Personal; active Space becomes unavailable. A later controller must allow explicit discard in that recovery state. The existing Space switch sheet discards both import and manual work when both exist and says “Discard work”. Manual-only remapping remains unchanged.
- Money uses `bigint` minor units inside the local evidence model. Task 03 must validate dates/money and convert to exact decimal strings at serialization boundaries; `JSON.stringify` cannot directly serialize this model. No persistence/HTTP serialization or review-edit model is introduced here.
- Android/iPhone lifecycle and Space-sheet acceptance remain pending the production adapter/route from later tasks. No native configuration or dependencies changed.
