# IP-07 consolidated handoff: Tasks 1–7

This is the single handoff report for IP-07. The original Tasks 1–3 notes are retained below, followed by Tasks 4–7 delivery notes.

- Unknown-operation recovery uses the existing `RESOURCE_NOT_FOUND` code. The application-error HTTP mapper previously omitted that code; it now maps to 404. No operation-specific not-found code or schema migration was needed.
- Recovery's `recover` unit-of-work capability translates only TypeORM PostgreSQL `55P03` errors, after the transaction promise has rolled back. Both actor/Space and operation-row locks use NOWAIT. A lock failure can occur after partial scope acquisition; the PostgreSQL suite checks those scope locks are released before returning pending. Other errors propagate, so callers must retain uncertainty.
- The new crash cases live in the existing Expense/Statement Import Space PostgreSQL suite and reuse its isolated database. They compose the real operation controller, authentication/provisioning guards, service and TypeORM stores. Test-only seams pause transactions after Rule, snapshot-row, Expense, Activity and operation-result writes; a separate connection calls `pg_terminate_backend`. Another seam destroys the HTTP response socket after commit. These cases compare financial records and revisions, not only response codes. The intentionally old admission timestamp is inserted at admission because the database correctly forbids changing it later.
- A GET racing archive may legitimately return pending while the original executor retains locks. The subsequent terminal lookup must retain whichever rejection won (`SPACE_NOT_WRITABLE` or `IMPORT_OPERATION_NOT_COMMITTED`); tests must not assume recovery always wins. Identity deletion removes Personal read authority, leaving status inaccessible rather than fabricating a failure outcome. Foreign members cannot recover the original actor's operation, including in archives.
- The mobile adapter now requires `ImportConfirmationApi.status(spaceId, operationId)` and strictly decodes pending/failure responses. Existing confirmation workflow test doubles were extended for that interface; production receipt/session/recovery UI integration remains for Tasks 4–6. Native restart/storage/accessibility acceptance has not been performed by this server/adapter work.
- Verification used a disposable PostgreSQL 16 container and all ten distinct database URLs required by the current runner. PostgreSQL network access and Docker require sandbox escalation on this Windows host. The task-only container was removed afterward. Migration/runtime packaging was unchanged.

## Tasks 4–7: integration nuances

- The production SecureStore owner is injected by `session-runtime.ts`; the application workflow remains native-independent for deferred-I/O testing. Receipt hydration runs before provisioning/Space selection. Restoration deliberately bypasses the remembered-Space fallback when an original receipt exists, including when that Space is inaccessible. The receipt uses Clerk's identity, never the API's local User ID.
- Successful financial completion and receipt acknowledgment are separate. The route selects recovery by receipt presence before inspecting the living handoff, so completion cannot send the screen back to file selection prematurely. The existing history route opens only while the original Space is active; committed history navigation acknowledges first, while unresolved history navigation retains the receipt. Status/retry taps share application-owned phase guards across both the persistent entry and import screen.
- A sent 400/403/404/409/413/415 is no longer a definitive local rejection. Only decoded committed success or authoritative GET `not_committed` releases the financial uncertainty; acknowledgment then releases the receipt/edit lock. Older confirmation tests were updated to require that distinction. Same-User renewal rebinds each explicit retry's generation, while cloning the in-memory attempt invalidates older responses without changing JSON/UUID/acknowledgments.
- Cleanup revokes ownership synchronously and queues deletion after in-flight writes. Both receipt epochs and session cleanup attempt versions matter: an older successful cleanup must not release a newer failed cleanup. Read/delete failures remain gated and retryable. Sign-out awaits durable cleanup before asking Clerk to terminate; expiry instead hides/retains work. `session.acceptedAccountDeletion()` is the accepted-deletion seam. Auditing mobile callers found no account-deletion endpoint caller or UI; that end-to-end coverage is still absent.
- Recovery adapts the verified `nny4o` and `VgDBB` nodes. Shared modal focus restoration now reaches the Close button through its native ref. The shared dialog keeps its existing radius; no dedicated recovery source board or native parity claim is introduced.
