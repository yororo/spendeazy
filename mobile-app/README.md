# Spendeazy mobile

## Expense API foundation

Use the shared [root glossary](../GLOSSARY.md), [Expense domain and mobile API contract](../docs/specifications/mobile-expense-domain-api.md), and [replacement ADR](../docs/adr/0004-mobile-expense-domain-and-contract.md) for the accepted target. Shipped API behavior is the exposed endpoints in the [OpenAPI contract](../api/docs/openapi.yaml). The mobile app signs in with Google through Clerk, lists authorized Spaces, creates manual Expenses, browses active and deleted Expenses, and edits, deletes and inspects Activity for manual and imported Expenses in writable Spaces. The Dashboard reports Monthly and Yearly actuals and exact active-Budget plans, shows monthly and Category charts, checks Monthly and Yearly limits, counts confirmed imports by Manila date, and opens filtered Expense lists. The Budget tab browses active and inactive Categories with All/Monthly/Yearly/Unset filters, Category-name search and name or exact monthly-equivalent sorting. Its plan totals include all active Budgets regardless of list filters. The tab also creates and maintains Categories, optional Monthly/Yearly Budgets and complete Exact/Contains Rule sets in one revision-checked save. Profile opens Invite Code management for creating, copying, rotating or revoking a code, previewing a saved invitation, and explicitly joining or declining. Archived Shared Spaces stay selectable as read-only history; their Expenses, Activity, and Statement Import history remain available. Statement import preview and confirmation remain unavailable.

The native client uses Expo Router and React Native. `npx expo install` selected the SDK 58 compatible set already in this project: `expo` 58.0.16, `react-native` 0.88.0, `expo-router` 58.0.24, plus `@clerk/expo` 4.14.1 and `@clerk/expo-google-signin` 1.1.0. This change does not upgrade the SDK. A local PDF.js parser prototype remains at `/parser-proof` and is not part of the signed-in tab bar.

Android emulator and physical-iPhone sign-in evidence is still required before this journey is accepted. Lint, typecheck, and the navigation tests do not replace that device run.

## API and device testing

The signed-in client uses the [OpenAPI contract](../api/docs/openapi.yaml): `PUT /api/v1/users/me` provisions/synchronizes the User, `GET /api/v1/users/me/spaces` lists authorized Spaces, `GET /api/v1/users/me/spaces/{spaceId}/reporting/dashboard` returns Monthly/Yearly Dashboard reports, and `GET`/`POST /api/v1/users/me/spaces/{spaceId}/expenses` browse/create Expenses, `GET /expenses/deleted` browses retained deletions, `GET`/`PATCH`/`DELETE /expenses/{expenseId}` reads, corrects and soft-deletes an Expense, and `GET /expenses/{expenseId}/activity` reads its Activity. Budget browsing reads `GET /api/v1/users/me/spaces/{spaceId}/categories` and each Category's `GET /api/v1/users/me/spaces/{spaceId}/categories/{categoryId}/configuration` for its current optional Budget. Sharing uses `GET`/`POST`/`DELETE /api/v1/users/me/invitations`, `POST /invitations/rotate`, `POST /invitations/claims`, `DELETE /invitations/claims/{claimId}`, `POST /invitations/claims/{claimId}/accept`, and `POST /spaces/{spaceId}/leave`. Statement Import history uses `GET /api/v1/users/me/spaces/{spaceId}/statement-imports`. The app supplies a Clerk session token, not a User id. Other contract endpoints do not imply that their mobile UI is implemented.

Google sign-in uses the native Clerk flow and requires a development build. API and app must use the same Clerk development instance; configuration and platform setup are in the runbook.

The root navigator protects the `(app)` and `(auth)` layouts using the current session. Keep an explicit layout in each group so Expo Router registers the group names targeted by those guards; without the auth layout, the sign-in screen is registered as `(auth)/sign-in` and bypasses the `(auth)` guard. The signed-out redirect explicitly targets `/(auth)/sign-in`: the auth group has no index screen, so its group-only URL can resolve to the generated not-found screen. Route-discovery and guard-destination regressions run with `npm test`.

The [session capability](src/application/session.ts) owns identity, Clerk session and Space transitions. Manual Expense input is kept in memory across expiry for the same identity. Explicit sign-out clears that draft and the Expense browse selection immediately; a different identity starts empty. Changing Space clears the selected Category, browse filters and scroll while preserving entered amount, description and date. Remembered active Spaces remain device preferences keyed by identity.

All current Spaces, Categories, Expense list/detail and manual submission requests use the [session request boundary](src/application/session-request.ts). Missing local credentials produce a sign-in issue without ending the session. HTTP 401 locks private routes and initiates one Clerk recovery; transport errors and invalid responses remain retryable issues. Requests check both their application scope and live Clerk credentials before reacting to outcomes. A delayed failure cannot terminate a replacement Clerk session. If Clerk termination fails, the sign-in action retries it before starting Google authentication.

The Clerk transport stays stable for the same Clerk instance and session while calling the latest committed token and sign-out callbacks. Clerk Expo recreates its token callback on render; using that callback as workflow identity would repeatedly restart Spaces loading. The Spaces provider render tests exercise this callback churn, refresh, token renewal and session replacement.

Spaces loading first provisions the signed-in User through the API. The workflow shares an in-flight provisioning request across refreshes and reuses success for that session; a failed attempt remains retryable. Identity changes during provisioning prevent the old workflow from reading Spaces. The API obtains the authoritative profile from Clerk; the app supplies no profile body.

The [Spaces workflow](src/application/spaces/workflow.ts) owns accessible selection, refresh and device-memory writes. [Expense controllers and views](src/features/expenses/) and the [Category configuration controller](src/features/categories/use-category-configuration.ts) consume the session capability; routes retain navigation. The Budget list uses [current Category configurations](src/features/categories/use-budget-categories.ts); its [calculation and sort rules](src/features/categories/budget-browse.ts) keep amounts in integer cents, compare exact monthly equivalents, and round only displayed totals. Search and list filters never change the active-plan total/count; inactive Categories are excluded from that plan. Changing Spaces resets the list controls, and returning from Category settings refreshes the current configurations. Private work is volatile and does not survive process termination. Shared Space invitations use a typed API adapter and sharing controller. An unsaved Expense must be saved or explicitly discarded before switching Spaces; an archive race that rejects a save keeps entered work available to inspect or copy. Statement Import remains a prototype apart from read-only history browsing and has not migrated to this capability.

The [Expense browse workflow](src/features/expenses/browse-workflow.ts) owns replacement, refresh, pagination and retry. Refresh invalidates any pending page; a late success or failure cannot restore older rows or clear the current loading state. Failed pagination keeps existing rows and retries the same cursor. Filters, full-selection totals and detail-return scroll memory remain owned by the Expense feature.

The [Expense detail workflow](src/features/expenses/detail-workflow.ts) loads one Expense and its Activity for the signed-in identity, active Space and Expense. Detail, edit and deletion responses are decoded by the shared Expense adapter before the workflow accepts them. Retry, and a change of identity, Space or Expense, discard an older success or failure. The view resolves current Category and member names, shows immutable import/source-row references, and presents before/after snapshots. Writable active Spaces can edit or soft-delete either source; deleted detail is read-only. `expense-edit-workflow.ts` validates the draft, sends only changed fields with the observed revision, retains failed drafts and requires review plus explicit continuation after a stale save. Successful mutations refresh the origin list while preserving its filters and scroll offset. Active and Deleted Expenses use separate list requests and scroll memory.

`npm test` covers the adapters, browse/detail workflows, Category draft preparation, and supplied-state views rendered with a native host substitute. These checks do not establish device accessibility or native acceptance. Native accessibility and installable-build evidence remain tracked separately in [#157](https://github.com/yororo/spendeazy/issues/157), [#158](https://github.com/yororo/spendeazy/issues/158) and parser launch [#138](https://github.com/yororo/spendeazy/issues/138).

The [manual Expense feature](src/features/expenses/use-manual-expense.ts) owns Category loading/retry and submission. Its [preparation operation](src/features/expenses/manual-draft.ts) returns field issues or normalized input using explicit time and destination-scoped Category eligibility. The view receives display state and intent callbacks; the route handles successful navigation after checking the initiating scope and form lifetime. Disposing the form invalidates its pending completion, including same-Space re-entry, without clearing retained draft work. Submission accepts one save at a time and remains completed after success. Expected failures preserve entered values; transport and invalid-response errors explain that the Expense may already exist. Retrying creation is an explicit User action, never an automatic replay. The API still enforces authorization, writable Space access and Category eligibility at save time. Manual preparation, workflow races, creation response decoding and supplied-state view checks run in `npm test`.

The manual form reads entered values from the subscribed session snapshot so React Compiler observes draft changes. A compiler-enabled controller regression checks successive edits and draft clearing in `npm test`.

The API's deterministic fictional seed is restricted to a specifically named disposable local database. See the API [seed instructions](../api/README.md#development-seedreset) before using `db:seed` or `db:recreate-seed`. API PostgreSQL automation creates fresh isolated databases; see [local checks](../docs/local-checks.md).

## Release evidence

Record the app/API revisions, native build profile, device model and OS, relevant configuration and observed result. Keep evidence sanitized: do not commit PDF statements, passwords, extracted text, financial screenshots or credentials.

Mobile lint, TypeScript and parser fixture checks are automated software checks only. Personal-use readiness also requires installable native builds, Android emulator and physical-iPhone journey evidence, and the remaining parser limits/device/cleanup checks in [issue #138](https://github.com/yororo/spendeazy/issues/138). No device certification is claimed by CI.
