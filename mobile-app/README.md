# Spendeazy mobile

Native Android/iPhone application built with Expo Router. Follow the [local runbook](../docs/local-testing.md) for installed development builds and device setup; Expo Go is not the acceptance target. [Coding standards](CODING_STANDARDS.md) describe feature/controller/adapter ownership. The [OpenAPI contract](../api/docs/openapi.yaml) owns shipped HTTP behavior.

Run `npm test`, `npm run statement-import:test`, `npm run lint` and `npm run typecheck` from this directory. Application tests include review/session lifecycle, confirmation serialization/controller and HTTP adapter parity checks. Parser fixtures use fictional data and establish no native device certification.

The [Statement Import feature guide](src/features/statement-import/README.md) owns extraction, review and the public confirmation handoff. Confirm supports final inspection and warning previews. Production submission remains disabled until #154 supplies durable receipt-before-send and recovery integration. #155 owns committed-import history/detail presentation. The [complete JSON envelope evidence](../api/docs/statement-import-envelope.md) records fitting and overflowing probes under the unchanged 1 MiB API limit. Native Android/physical-iPhone acceptance and #138's parser launch limits remain pending.

Profile supports provider-owned name/photo editing and read-only email. Rebuild development clients after the ImagePicker plugin/package change using the [native runbook](../docs/local-testing.md); an Expo reload alone does not install native modules. Enable first/last-name editing in the development Clerk instance. Actual photo upload, permissions and profile refresh still need device/provider acceptance.

Account settings offers explicit permanent-deletion confirmation. A minimal SecureStore marker binds submitted/accepted intent to the initiating provider identity/session before any request is sent; no token or financial data is persisted in it. Root navigation reconciles that marker before provisioning Spaces. Uncertain submission gates financial screens and offers Check status/idempotent retry. Accepted cleanup continues server-side after closing/sign-out; only authenticated completed status or DELETE 204 proves completion. Session revocation can end status access first. Explicit sign-out removes the identifying marker; it never claims completion.

The app clears financial state, drafts, receipt storage, remembered Space selection, app-created PDF resources and picker image copies through the application cleanup gate. Failed cleanup remains blocking and retryable; Appearance stays on the device. Late responses and native picker/copy work are fenced before cleanup. This device cleanup cannot erase an offline device remotely. See the [consolidated IP-09 evidence and handoff](../docs/agents/implementation/IP-09_Report.md) for verification and remaining Android/iPhone/real-Clerk checks.
