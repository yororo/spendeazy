# Local Statement Import

`index.ts` exposes the application-owned `statementImportStore`, evidence/review types and `validateReview` for #153. `ready.result` initializes review once; the scoped controller loads Categories and the complete Rule collection for the original destination. All matching, corrections, inclusion decisions and staged Rules remain local. Update performs only Category/Rule GETs, with no persistence requests.

Continue dispatches `continued` through the store with a current captured review scope and injected time. Only a writable, authenticated, current draft with a usable catalog can reach `review-ready`. Its `review.handoff` is an immutable snapshot of owner, Space/draft identity, applied review revision, unchanged original evidence, source-ordered rows (including omissions), assignment context, staged Rule intents and catalog revisions. Included rows have exact canonical decimal-string `amount`; excluded rows have `amount: null` and retain their applied values plus original evidence. Bigint evidence remains internal: do not JSON-stringify the handoff. `validateReview` is a pure validation/export seam; use the guarded store transition for application navigation.

Continue now opens Confirm for final inspection, scoped preview and explicit warning acknowledgment. `backToReview(scope)` retains queue, filters and editor buffers before submission. Tentative or applied changes invalidate the handoff and preview/acknowledgment; applied edits increment the review revision. Catalog refresh retains manual/valid mappings, exposes inactive assignments for explicit resolution and rechecks staged intents against refreshed Category/Rule revisions. Conflicting or inactive staged targets block Continue.

`ImportResult` holds file identity (SHA-256 of decoded PDF bytes), date-only strings, exact bigint centavos, original controls and ordered rows with page/order identities, classification evidence, exclusions, page outcomes and advisory warnings. `decimalAmount` converts bigint to an exact decimal string at a future serialization boundary; do not JSON-stringify the local model directly. Original descriptions, references, dates and amounts are evidence. No page text/geometry, password or PDF bytes enter this store. Retained results are memory-only: Back/backgrounding retain them, process death loses them, same-owner expiry suspends them, and sign-out/different identity/discard clears them. Interrupted extraction requires reselection.

The root extraction host survives route Back. Each operation uses a fresh host with its own ID; bridge decoders reject stale IDs and malformed data. Password input is short-lived and submitted directly to PDF.js's pending password callback. Terminal outcomes remove the host and clear transient transfer references. JS/native memory cannot promise secure erasure.

Only BDO Amex PHP, EastWest Visa PHP/Peso and GCash Transaction History are recognized. Mixed/ambiguous identities and non-PHP card variants are rejected. Rows follow engine stream order, never geometry sorting or description deduplication. GCash uses explicit debit/credit columns with the recognized table header, or an exact adjacent balance movement equal to the row magnitude. It never derives direction from descriptions or adjusts direction to satisfy controls. Unsupported/malformed rows cause a partial warning when other rows remain usable. Unknown dates/directions remain ineligible. Missing controls and mismatches retain rows; reconciliation compares original activity, including incoming/excluded rows. Text extraction always leaves completeness uncertain. Blank pages and pages containing logos do not establish missing activity or scanning.

## Scoped files and startup

Before selection the workflow sweeps its dedicated `Paths.cache/statement-import` directory and only the direct picker cache children recorded in `Paths.document/statement-import-cleanup.json`. The pinned SDK uses `Paths.cache/DocumentPicker` on Android and iOS. URI validation rejects traversal, descendants and unrelated paths. Never sweep the whole picker directory or general cache. Picker copies are journaled even when their operation has already been cancelled; originals are never deleted. Transfer into a random owned filename must finish before removing staging. Read the owned copy, hash actual decoded bytes, then delete it. Password retry uses only the engine's live loading task.

Cleanup failure blocks new selection and offers retry. Startup retries journaled cleanup. The journal stores random staging URIs only. There is an unavoidable crash interval between OS creation of a picker copy and receipt/journaling of its URI; this code cannot discover that orphan without an unsafe general sweep. Filesystem writes, process termination and native worker teardown need further device evidence under #138.

The 10 MiB/100-page guards are development safety caps, not supported limits. #138 still owns peak memory (including base64/decoded-byte transfer copies), runtime, older-device floors, crash intervals and certified limits. No OCR or remote fallback exists.

## Confirmation and recovery handoff

The shipped [OpenAPI contract](../../../../api/docs/openapi.yaml) defines `POST /api/v1/users/me/spaces/{spaceId}/statement-import-previews`, PUT and GET `/api/v1/users/me/spaces/{spaceId}/statement-import-operations/{operationId}`, and import history/detail GETs. Preview stores no draft. Confirm shows original Found count and exact included/excluded counts, Category totals and fixed destination. Warnings require explicit Import anyway using every displayed ID and digest. Only an authenticated committed response or authoritative GET `not_committed` resolves a sent operation. HTTP errors (including 404, payload conflict and envelope rejection), unreadable responses and transport failures retain uncertainty. A terminal warning failure retains its safe refreshed preview; acknowledgment permits correction/new UUID while preserving living review and staged Rules.

`session.confirmation` owns the workflow across route remounts. It fences completions by owner, session generation, draft/handoff revision and request identity. Submitted UUID and actual JSON are frozen in memory; explicit live retries reuse both exactly, including warning acknowledgments, after same-User credential renewal. Old requests cannot deliver results with renewed authority. Saving/recovery blocks editing, discard and independent import. Success completes living work and refreshes resources once; acknowledgment separately clears the matching receipt.

`confirmation-receipt.ts` serializes all receipt I/O through the application-lifetime owner. SecureStore key `statement-import-receipt.v1` contains exactly `{userId, spaceId, operationId}`; User identity is Clerk's ID. The production hook awaits durable persistence before every PUT. Rows, amounts, Rules, passwords, PDF data and frozen JSON never enter receipt storage. Failed read/delete blocks restoration or acknowledgment and offers retry. Explicit sign-out/different identity destroy private memory and revoke receipt epochs immediately; queued cleanup follows outstanding writes. Expiry retains living work and receipt while signed-out routes hide them. `session.acceptedAccountDeletion()` shares explicit cleanup; no mobile account-deletion caller/UI exists.

Spaces startup hydrates before provisioning/catalog selection and remembered-Space fallback. Matching recovery selects the exact original accessible Space, including archive; an inaccessible original stays unresolved without Personal fallback. Restart and Check status issue GET only. GET may reconcile orphaned operation metadata, as described by the shipped contract; pending/404 never authorize another operation. Archived destinations permit lookup but disable financial retry. The recovery screen works without a handoff, shows immutable committed totals, and explains that restart loses review data. Close/Android Back warn that saving may still complete; dismissal retains a persistent Check import status entry. Tabs/Add and destination switching remain blocked until acknowledgment. History opens the existing route only when its active Space is the original receipt destination. The committed history action acknowledges first; unresolved history navigation retains the receipt.

Import detail already exposes immutable confirmation totals/evidence independently of mutable Expenses; #155 owns their full history/detail presentation. [Envelope measurements](../../../../api/docs/statement-import-envelope.md) show fitting and overflowing complete JSON probes under the unchanged 1 MiB limit; 3,000-row probes require a follow-up support decision. They do not certify #138 parser limits. Native Android/physical-iPhone final inspection, light/dark/large-text/accessibility checks and successful submission after receipt integration remain pending.
