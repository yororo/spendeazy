# On-device Statement Import parser (proof of concept)

This app answers one question: can a phone parse a Statement Import PDF with the same pdf.js build the web app uses, without calling a backend?

It is not the product. There is no sign-in, no API client, no categorization UI, and no way to save transactions.

## What runs where

```text
pick PDF or bundled fixture
  read bytes
  delete the document-picker cache copy
  hidden WebView (file:// HTML, one classic IIFE)
    pdf-parse 2.4.5 / pdfjs-dist 5.4.296
    globalThis.pdfjsWorker set, so parsing stays in-thread
    getText({ pageJoiner: "" })
  React Native joins pages with "\n"
  shared transformStatement (Hermes)
  show provider, count, total, error code, text SHA-256, elapsed time
  show "network requests: 0"
```

The WebView page is generated from `pdf-parse`'s browser build and the worker file the web app copies (`dist/pdf-parse/web/pdf.worker.mjs`). No CMap, standard-font, or CDN URL is configured. A content-security policy of `connect-src 'none'` and a `fetch` / XHR / WebSocket replacement refuse remote URLs inside the page. `onShouldStartLoadWithRequest` returns false for any URL that is not `file:`, `about:`, `data:`, or `blob:`.

`originWhitelist` is `['*']` on purpose. `react-native-webview` opens a URL in the system browser when it fails the whitelist, which would itself be a network request. The load callback is what blocks the navigation.

## Where the parsers come from

The TypeScript parsers are not copied. `npm run prepare:poc` bundles these modules with esbuild:

- `web/src/features/statement-import/statement-parser/*` (`transformer.ts` and the files it imports)
- `web/src/shared/money`
- `cleanDescription` from `web/src/features/statement-import/statement-import-utils.ts`

The bundle is `src/generated/statement-parser.js`. Metro loads that file. The web app's API client, Clerk, and categorization UI are not in the bundle.

`pdf-extractor.ts` is not imported. It points pdf.js at a Vite worker URL (`import.meta.env.BASE_URL`). The WebView script repeats the same `PDFParse` options (`stopAtErrors: true`, `getText({ pageJoiner: "" })`) and the same password / unreadable error codes.

The fictional fixtures are not copied either. Metro bundles `web/e2e/fixtures/spending-journey.pdf` and `spending-journey-encrypted.pdf`. The encrypted password `fictional-journey-only` is the public test password documented next to those files.

`pdf-parse` is pinned to `2.4.5` (which depends on `pdfjs-dist` `5.4.296`), the same versions as `web/package.json`.

## Scripts

```bash
cd mobile-poc
npm install
npm run prepare:poc   # rebuild the WebView page, parser bundle, and baseline
npm run baseline      # Node-only refresh of src/baseline.json
npm run verify:webview
npm run typecheck
```

`verify:webview` loads `assets/parser-webview.html` from `file://` in Playwright Chromium and WebKit. It checks that the joined text SHA-256 matches `src/baseline.json`, that a wrong password reports `password`, and that the only browser request is the HTML file.

## iOS Simulator (Mac)

iOS cannot be built on Linux.

1. Install Xcode and CocoaPods. No Apple Developer Program account is required for the simulator.
2. `cd mobile-poc && npm install && npm run prepare:poc`
3. `npx expo prebuild --platform ios`
4. `npx expo run:ios`
5. Tap **Run self-test**, or open `spendeazy-parser-poc://self-test`.

## Android, local development build

Expo Go will not run this app. Do not use an Expo or EAS account.

1. Install a JDK, the Android SDK, and an emulator or a device with USB debugging.
2. `cd mobile-poc && npm install && npm run prepare:poc`
3. `npx expo prebuild --platform android`
4. `npx expo run:android`

`plugins/without-internet.js` removes `android.permission.INTERNET` during prebuild, including the copy libraries merge in. A normal debug build still loads JavaScript from Metro on your computer; that connection is the dev server, not the parser. The WebView document itself is written under the app cache and loaded with `file://`.

A release APK embeds the JavaScript bundle and does not need Metro:

```bash
cd android
./gradlew assembleRelease
```

The debug keystore generated by prebuild signs that release build in this proof of concept. Replace it before any real distribution. This folder is not for distribution.

On a phone: enable USB debugging, then `npx expo run:android --device`.

## Self-test

**Run self-test** parses both bundled fixtures, checks the text SHA-256, provider, transaction count, and total against `src/baseline.json`, tries the encrypted file with the wrong password, then probes `fetch` and an `https:` navigation.

A deep link runs the same check:

```text
spendeazy-parser-poc://self-test
```

```bash
adb shell am start -a android.intent.action.VIEW \
  -d "spendeazy-parser-poc://self-test" \
  -n com.spendeazy.parserpoc/.MainActivity
adb logcat -s ReactNativeJS:V | grep POC_SELF_TEST
```

`POC_NETWORK_BLOCKED` is logged when a non-local WebView URL is refused.

## A real statement on your own device

Use **Pick a PDF**, enter the statement password if the file has one, then **Parse**. The picker copy in the cache is deleted after the bytes are read. Do not commit a real bank PDF, and do not paste a real statement into an issue or log. The screen shows aggregate fields and a SHA-256 only; it does not print the statement text.

### Android emulator

A release APK was built with `./gradlew assembleRelease` (`x86_64`, JS bundle embedded, signed with the debug keystore). `aapt dump permissions` lists `READ_EXTERNAL_STORAGE` (max SDK 32), `WRITE_EXTERNAL_STORAGE` (max SDK 32), `SYSTEM_ALERT_WINDOW`, and `VIBRATE`. There is no `android.permission.INTERNET`. `dumpsys package` on the emulator agrees.

`/dev/kvm` exists, and `emulator -accel-check` reports KVM, but creating a vCPU hits `kernel BUG at arch/x86/kvm/x86.c:702` in `kvm_arch_vcpu_create`. Hardware acceleration cannot be used on this kernel. The emulator was booted with `-accel off` (TCG).

With `-gpu swiftshader_indirect` and with `-gpu swiftshader`, the guest exposes OpenGL ES 3.0 only. The React Native screen renders, including the deep link `spendeazy-parser-poc://self-test`. WebView then logs `eglCreateContext: EGL_BAD_CONFIG` for ES 3.2 and ES 3.1. About 20 seconds later the sandboxed renderer dies:

```text
signal 5 (SIGTRAP), code 128 (SI_KERNEL)
pc 00000000017971cc libwebviewchromium.so
```

That address is an intentional `ud2` after a check that a field is less than 2. The same trap happens for a one-line page (`<script>Poc.ready('small')</script>`), so it is the emulator WebView, not the pdf.js bundle. `--js-flags=--jitless` hits the same instruction. No `POC_SELF_TEST` line is logged, and the UI never leaves "Loading local parser…".

`-gpu swangle` advertises OpenGL ES 3.1 (ANGLE on SwiftShader) and then the Android system server dies with `Lost network stack`. `-gpu software` selects that same swangle GLES path. `-gpu host` needs a host GPU and KVM, which this VM does not have.

A physical Android device, or an emulator whose GLES driver can create a WebView context, is what can finish the on-device self-test. The APK is buildable on Linux without an Expo account.
