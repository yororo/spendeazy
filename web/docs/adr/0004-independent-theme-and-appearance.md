# Independent Theme and Appearance preferences

Technical and Playful are visual styles independent of the existing Light/System/Dark Appearance preference. Both Themes support either resolved Appearance, and changing Theme preserves the Appearance choice. Technical is the default and retains the current design.

Both preferences belong to the browser, persist across reloads and sign-outs, synchronize between tabs, and apply before the first render. This matches existing Appearance behavior and avoids introducing account preferences into the API User Profile contract; different Users of the same browser inherit its visual preferences. If browser storage is unavailable, a selection lasts for the current visit.

Theme applies globally to every route and overlay through presentation tokens and shared primitives. It preserves financial data, in-progress forms and Statement Import review, filters, selected Space, scroll position, Category Colors, page structure, spacing, control dimensions, and responsive breakpoints; new fonts may change natural text wrapping. Separate preference dimensions avoid coupling a visual style to a light or dark palette, and one application structure avoids maintaining duplicate page implementations. Technical and Playful reuse the same pages and components; style differences belong in theme tokens and shared component styling. A theme-specific component is justified only when an existing component genuinely cannot be reused, and the exception must document that limitation.

The Settings button sits beside the User's name and expands an inline section in the profile card, shared by the desktop sidebar and mobile/tablet navigation drawer. Theme and Appearance have separate labelled selectors in that section, and Sign out remains below. Theme offers only Technical and Playful; selection applies immediately while leaving Settings open, and Settings toggles the section closed. Following the User's browser feedback, Theme uses a dropdown rather than inline radios so its composition can accommodate future choices. Playful has no hard UI surface corners, including Space labels/icons and profile initials; the unchanged pixel logo and structural viewport/dividers retain their geometry. Keyboard interaction and visible focus follow existing accessible control rules.

The first Playful Theme uses the Emerald and Honey treatment documented in the [archived Dashboard prototype note](../../../docs/archive/web/dashboard-theme-prototype.md) and its original `.tsx`/`.css` references preserved in Git, superseding the earlier violet/lavender palette. The reference supplies ivory (`#FAF8F1`) backgrounds, emerald (`#087443`) primary actions and Total spend surface, white supporting cards, green (`#24A66A`) chart bars, and a restrained honey accent for Manage Budgets (`#FFF0BB` surface, `#C68A16` border, `#67450A` text), together with rounded edges and softer borders. The original profile settings reference in `design/ui-design.pen` still guides the selector's composition, adapted to Emerald and Honey. Playful uses Nunito for headings and prominent metrics and Nunito Sans for body text, navigation, controls, and tables, retaining tabular numerals for financial values. Technical keeps Geist and Geist Mono. Existing wording, icons, logo, and content remain; existing accessibility rules take precedence over illustrative mockup dimensions. The Playful dark palette extends Emerald and Honey with readable contrast and distinct status states. The prototype's development-only URL controls, Dashboard-only scoping, and forced light appearance are evaluation mechanisms, not production requirements.

The User confirmed the complete shared understanding and requested an implementation-ready specification through to-spec. The specification is [GitHub issue #89](https://github.com/yororo/spendeazy/issues/89). This ADR records the accepted design; implementation is a separate task.
