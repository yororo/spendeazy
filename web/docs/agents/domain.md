# Domain Docs

This is a single-context repository.

## Before exploring

- Read the root `CONTEXT.md`.
- Read relevant decisions under `docs/adr/`.
- If a file is absent, proceed silently; domain-modeling workflows create documentation lazily when terms or decisions are resolved.

## Vocabulary

Use canonical terms from `CONTEXT.md` in specifications, issues, tests, and implementation. Avoid synonyms explicitly rejected by the glossary.

## Decisions

Surface any conflict with an existing ADR rather than silently overriding it.
